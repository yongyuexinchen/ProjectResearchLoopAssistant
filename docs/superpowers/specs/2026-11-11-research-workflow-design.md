# 工程调研向导与交互架构图

用户目标：通过下一步完成项目、资料和调研偏好的配置，提交后后台自动采集、分析、生成架构图与报告，直接看到真实进度及结果。架构图支持整图鼠标拖动、滚轮缩放、适应屏幕与全屏；用户已明确暂不需要单节点布局编辑。

## 实现选择

沿用现有 Next.js、FastAPI、LangGraph 和数据库 Worker。选择后台持久任务，而非浏览器串行调用：关闭页面不会中断调研。配置采用单次原子提交，避免无效资料留下半成品项目。保留现有详情工具页，主路径以向导和运行结果为中心。

## 行为与边界

- 四步配置：项目目标、输入资料、调研偏好、确认启动；返回上一步保留输入。
- 后台阶段为 collection、analysis、architecture、report；进度从持久事件推导，报告保存前不能显示 100%。
- 没有代码目录时架构图明确跳过并提示原因；采集失败、取消、暂停、重试有独立状态。
- 自动流程不会代替人工审批，不修改被分析工程。没有可用模型时明确说明确定性分析回退。
- 架构图使用安全 Mermaid 渲染，缩放以鼠标位置为中心，按实际容器尺寸适配；全屏可按 Esc 返回。
- 不改动本地密钥，不进行付费模型验证，不发布或推送。当前目录没有 Git 元数据，在用户指定目录内直接修改。

## 调研方式特异化

五种调研方式共用同一套证据、校验和运行隔离，但报告不再套用同一份模板：

- 每种方式声明受众、核心问题、交付物、关注点、分析指令和有序章节计划（`report_sections` / `section_plan`）。
- 所有方式都先渲染「项目速览」：项目是什么、主要能力、工程特点、技术形态和资料缺口；事实直接写入正文，依据单独列在节末（README 路径/章节、依赖清单、代码库扫描），不再在每句话后面重复“依据 README”。
- README 表格会解析成可读的能力条目，不再把 `| Domain | ... |` 原样塞进报告。
- 入口识别覆盖 Next.js App Router、React 入口、Express/Node 和 Python main/app；模块与关键代码只从源代码文件中选择，过滤 `public/` 图片、`__pycache__`、`.pyc`、测试文件和构建产物。
- 报告导出文件名绑定项目和调研方式：`项目名-调研档位-调研报告-日期-报告短ID.md/pdf`。
- 快速接手：接手指南、启动线索、架构地图、阅读路线、上手前确认事项。
- 架构理解：系统定位、模块边界、主流程（静态推断）、外部依赖、扩展点、验证缺口。
- 二开评估：改造面、可行性、风险、测试与配置复杂度、分期方案、开工前证据。
- 教学拆解：教学目标、章节、代码讲解顺序、难点、练习、教学材料缺口。
- 交付验收：范围、完整性清单、可启动性、文档运维缺口、验收问题与结论。
- 确定性分析会按方式补充不同的发现/风险/建议；LLM 分析与报告提示词携带相同的章节计划，模型补充内容优先合并进对应章节。
- LLM 提出的高影响问题降级为 advisory（保留原始等级），避免自动任务因为模型建议反复暂停；确定性高影响问题仍会暂停等待用户输入。
- 同一 run 重新分析会替换旧证据/发现/风险/建议和未回答旧问题，已生成报告快照的 run 不受影响。

## 接口

POST /projects/setup 接收项目字段与 sources，返回 RunEnqueueRead。
POST /projects/{id}/workflow 启动现有项目的自动任务。
GET /projects/{id}/workflow?run_id= 可选运行，返回 run、stages、progress、status、error、report、architecture_count、warnings。
复用现有运行持久事件流，自动连接、断线重连并在组件卸载时中止连接。

## 验证

后端回归与新增工作流生命周期测试；前端类型检查和生产构建；本机浏览器检查向导、运行进度以及架构图拖动缩放。已有基线为 266 通过、2 失败、1 跳过，失败分别涉及本地演示目录假设与 HTTP 异常类型。
